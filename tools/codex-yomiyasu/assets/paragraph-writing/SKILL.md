# paragraph-writing — 段落から論旨を組み立てる

読み手が要点とその根拠を追えるように、文書全体と段落を構成する。文体や語尾の一律矯正ではなく、どの情報をどこで説明するかを扱う。

## 適用と保持

- 現在の依頼、読み手、文書の目的、既存の様式を優先する。「本文だけ」なら構成メモや評価を出力しない。
- 原文と提供資料の事実、主張、数値・単位、専門用語、条件、否定、推量、責任主体、因果・時系列、義務と推奨の違いを保持する。未確認の根拠や具体例を作らず、論証の空白を断定で埋めない。
- 引用・コード・数式・ID・リンク・表・手順番号を保つ。比較や独立した完了条件に有効な箇条書きは残す。
- 語句だけの修正、構成を維持する指定、元から論旨を追える箇所には、段落の並べ替えを加えない。

## 文書と段落の構成

1. **読み手が知りたいことを定める。** 何を理解・判断・実行できればよいかを確認し、本文の主張と根拠、残す条件を押さえる。用途が明確なら追加質問は不要。
2. **段落の役割と順序を決める。** 結論、背景、根拠、具体例、条件・限界、次の行動のうち必要な役割を対応づける。同じ話題が離れて繰り返されていないかを確認し、意味と比重を保てる範囲でまとめる。役割名を機械的に見出しや本文へ書かない。
3. **各段落を一つの論点で展開する。** 原則として冒頭でその段落の要点を示し、後続の文で理由、説明、根拠や例を具体化する。冒頭だけ読んでも段落の話題を追えるようにする。話題が変わる位置で分け、段落数・文数・文字数は固定しない。
4. **段落間の関係を確かめる。** 後の段落が前の内容を説明するのか、条件を加えるのか、別案を比較するのかを確認する。必要なつながりだけ表現し、接続詞を一律に足さない。用語や指示語の参照先が分かる位置に説明を置く。
5. **組み替えた意味を読み直す。** 結論を前へ移しても条件・未測定事項が隠れていないか、根拠が別の主張を支えるように見えないか、元の因果・否定・比重が変わっていないかを確認する。不明な関係は不明のまま扱い、必要な一点を確認する。

## 用途に合わせる

- **報告・Issue/PR・意思決定文書**：結論、現在の状態、依頼や変更後の振る舞いを早めに示し、それを判断するための根拠・条件・次の行動へつなげる。背景が結論の理解に不可欠なら、その前提だけ先に説明する。
- **技術解説・研究文書**：概念の前提や比較条件を理解できる順に置く。要約では結果と限界を早めに示し、導出・証明は必要な順序を保つ。結果、解釈、仮説、未測定を混同しない。
- **メール・応募書類・随筆など**：読み手の目的と既存の形式に合わせる。要望・条件、実績と強み、物語の展開などを、一律の結論先行／結論後置に当てはめない。

用途ごとの組み替えや「変更しない」例が必要なら [references/examples.md](references/examples.md) を読む。

## yomiyasuとの併用

単独で使える。yomiyasuも適用する場合は、構成の整理を一度行ってから同じ下書きの表現を仕上げる。すでに構成を点検済みなら繰り返さない。このSkillからyomiyasuを再帰的に呼び出さない。構成を変える必要がない文章はyomiyasuの局所修正に任せる。
