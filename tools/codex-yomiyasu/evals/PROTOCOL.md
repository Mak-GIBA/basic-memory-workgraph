## 比較の切り分け

まず「規則をすべて読み込んだときの文章生成」を比較します。上流だけ、既存の三スキル、今回の統合スキルの3条件に、同じ上流原本を与えます。既存スキルが最初から持っている段落・意味保持の指示を省いて、弱い比較対象を作ることはしません。

上流の取得元tagとcommit、各規則ファイルのSHA-256、モデル名、reasoning設定、CLI版、実行環境、出力、失敗と再試行を記録します。生成順は固定seedで入れ替え、1課題1条件ごとに新規セッションを使います。同じ会話で旧版→新版の順に書かせる比較はしません。

12課題×3条件×1回で36出力、3回なら108出力です。モデル利用枠や料金を消費するため、まず1回で実行条件を確認します。モデル温度など、CLIで制御できない条件は「未制御」と記録します。

## 比較用プロンプトの準備

元リポジトリのcommit `f0efd23a53c1c1cd028775aa415cc3f34ca5661a` にある `tools/codex-yomiyasu/assets` を別の作業コピーへ保持します。上流原本は、この提案版で導入済みの`yomiyasu/upstream`を共通利用できます。

```bash
python3 tools/codex-yomiyasu/evals/prepare_generation_eval.py \
  --upstream-dir "$HOME/.agents/skills/yomiyasu/upstream" \
  --baseline-assets /path/to/baseline/tools/codex-yomiyasu/assets \
  --out /path/to/new-evaluation-directory \
  --repeats 1
```

このコマンドはすべての規則をプロンプトに展開するため、ネイティブなSkillの自動選択や参照ファイル取得の成功率を測るものではありません。参照資料の必要時読み込みも再現しません。入力文字数はmanifestに記録しますが、トークン数は実際の実行ログから取得します。

生成前に評価環境のユーザー／プロジェクトの文体指示・スキル・MCP設定を確認し、各条件が同じ環境で動くようにします。評価用の独立環境を使い、認証ファイルを配布物やGitへ含めないでください。入力プロンプト内の指示だけで、他の既存設定の影響を完全に除去できるとは限りません。

Codexの非対話モードで実行する場合、各プロンプトを標準入力で渡し、`--json`のイベントと`--output-last-message`の完成稿を別々に保存します。例示のモデル名は、実際の環境で使うものへ置き換えます。

```bash
codex exec --sandbox read-only --skip-git-repo-check --ephemeral \
  --model YOUR_MODEL --json \
  --output-last-message outputs/J0001.md \
  "標準入力の執筆課題に、指定された規則を用いて回答してください。" \
  < prompts/J0001.md > outputs/J0001.events.jsonl 2> outputs/J0001.stderr.log
```

このCLIの例は公式非対話モード資料に基づきますが、この配布時点の実行環境ではCodex自体が未導入のため、実行していません。自分のCLIの`codex exec --help`と照合してください。テキスト生成の比較では、追加ツール使用が発生した試行は別記します。

## 採点

採点者には原稿／素材と完成稿だけを渡し、使用条件、プロンプト、manifest.private.jsonを見せません。`ratings.blank.jsonl`は空欄の採点票で、実施済みの点数ではありません。独立した2名による評価が望ましく、生成と同じモデルだけの自己採点は別欄にします。

意味の改変、数値・否定・主体・義務の変更、指示者向け説明の残存は重大項目として、平均点に埋めません。その上で、段落の統一性、根拠と主張の対応、段落間の一貫性、日本語の自然さ、読者適合を0〜4で採点します。

0は目的を満たせない、1は大幅な修正が必要、2は部分的な修正が必要、3はそのまま実用可能、4は内容と表現が十分に対応し修正の必要がほぼない、という基準です。必ず該当箇所と理由を短く記録します。0.5点の差を精密な測定値として扱いません。

採用候補の条件は、意味の重大な改変を増やさず、読者境界の混入を減らし、段落と自然さの両方を悪化させないことです。同率なら短い規則と低い運用負担を選びます。成功例だけを抜き出さず、課題単位の対応のある差と、失敗例を提示します。次の版を調整したら、未使用課題で再確認します。
