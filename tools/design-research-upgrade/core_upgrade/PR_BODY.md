# 要件駆動のコアロジック分解と研究結果の統合

## 変更
要件から研究が必要な判断単位を切り出し、テーマごとに約5方式を比較する。
共有入出力・評価条件を固定して依存/資源に応じた実行バッチを作る。
同じprojectは既存ロックのまま直列化。独立コピーを使う並列実行はホスト担当であり、このCLIは起動しない。
テーマごとの研究計画スナップショットを実runへ接続する。
新規design binding v2は多対多の研究→設計、標準実装の既存根拠、統合評価の状態を扱う。
図解・提案手法章・reassess・ユーザー懸念から要件を作る既存拡張を保持する。

## 検証
validation/workstreams-summary.jsonと実ログを参照。
完全な実リポジトリの回帰、インストーラー実再生成、実モデルの並列実行は未検証。
既存v1適用済みチェックアウトへ自動上書きしない。PR自体はこのパッケージから作成しない。
