# 既存稼働システムの後付け整理
コード、README、DB定義、設定、テスト、CI、運用資料を読んで対象範囲の現状を整理する。
まず全体像、次に重要・障害が多い機能を優先する。全システムの再実装を始めない。
確認したcommit/branchと稼働中releaseの関係を記録する。本番確認はアクセス許可後だけ。
As-Is(実装から観測)、合意済み仕様(出典付き)、To-Be(提案)を分ける。
現在の二重登録・データ漏れ等を正しい仕様として追認しない。
既存資料は正本として活かし、新規資料の内容と競合する場合は確認事項にする。
期待挙動を確認するcharacterization testと、望ましい振る舞いのregression testを区別する。
文書の整理、問題/リスク、改善候補、確認質問、検証計画を提示していったん停止する。
