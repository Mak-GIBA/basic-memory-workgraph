# ガバナンス・承認

System: @SYSTEM@ / Status: draft

## 承認原則
- 文書作成、レビュー資料作成、承認は別イベントとして扱う。
- 沈黙、次の話題への移動、過去の一般的なOKを今回の承認とみなさない。
- `approved`には、`$upstream-review`で固定したreview packetと、`$upstream-approve`によるhash-bound approvalを対応させる。
- 承認後に本文が変わった場合は `STALE_APPROVAL`、上位の要求・目的が変わった場合は下流を `STALE_DEPENDENCY_APPROVAL` として再レビューする。
- 承認状態と、アプリの実装・動作検証状態を分ける。

## Approval profiles
- `small`: scope → solution の2段階。小規模変更向け。
- `normal`: intent → requirements → solution の3段階。通常の既定値。
- `critical`: purpose → stories → requirements → design → verification の5段階。重要・高リスク案件向け。

## 記録先
- review packet: `governance/reviews/`
- approval ledger: `.specify/workbench/approvals.jsonl`
- 人向け承認一覧: `governance/approvals.md`

## 注意
これらはローカルのワークフロー証跡であり、署名・本人認証・改ざん耐性を提供するものではない。
