# 認知負荷のTips

ユーザーが頭の中で覚える・探す・比較する・対応付ける・推測する・行き来する負担を
見つけ、その作業を画面が支援できるか考える。要素数やクリック数の小ささだけで
評価せず、理解、判断、発見しやすさ、操作の完了を確認する。

この表は、提供されたUI/UX設計Tipsの29項目を設計と確認へ対応付けたもの。
詳細な由来は[出典](sources.md)を参照する。案件に関係する行を選んで使い、
候補表示、最近使った項目、自動保存等を一律に新機能として追加しない。

## 6分類と29項目の対応

| 分類 | 元の項目 | 設計・修正で行うこと | 実画面・操作での確認と例外 |
|---|---|---|---|
| 削減 | 1 注意を向ける情報 | 主な作業に必要な情報を優先し、競合する情報を整理する | 重要な対象や操作が見つかるか。必要な情報まで削らない |
| 整理 | 2 異なる目的の混在 | 顧客、契約、分析など意味のまとまりを作る | 現在の場所の役割が分かるか。関連作業を無理に別画面へ分断しない |
| 整理 | 3 要素の種類 | 同じ意味の情報・操作には同じ表現を使う | 状態や操作を画面ごとに学び直さないか。比較に必要な表現の違いは保つ |
| 記憶の外部化 | 4 覚えながら操作 | 対象名、入力、選択、条件を画面と遷移先に残す | IDの暗記・転記、再入力、往復が必要にならないか |
| 記憶の外部化 | 5 Recognition | 選択肢や意味の分かるラベルを使う | 候補から判断できるか。最近の項目や検索候補は必要な場合だけ使う |
| 行動支援 | 6 チュートリアル依存 | 必要な説明を必要な場所とタイミングに置く | 初回説明を覚えていなくても進めるか。プレースホルダーだけをラベルにしない |
| 近接 | 7 関連情報の距離 | 入力とエラー、設定と説明、グラフと凡例を近づける | 離れた情報を覚えて対応付ける必要がないか |
| 記憶の外部化 | 8 比較の同時表示 | 同じ観点の比較を揃えて見せる | 別画面を往復して比較しないか。Mobileでは読みやすさも保つ |
| 整理 | 9 Chunk | 意味でグループ化し、見出し・配置・余白で示す | カードの枠だけで関係を表していないか。無関係な情報をまとめない |
| 優先順位 | 10 重要度 | 位置、見出し、余白、文字の強弱を使う | 最初に見る情報が分かるか。強調を増やして互いに競合させない |
| 優先順位 | 11 Primary Action | 現在の対象・作業の主要操作を明確にする | 同じ強さの操作で迷わないか。複数の必要な操作を一つへ制限しない |
| 削減 | 12 装飾・不要情報 | 完了や理解に役立たない装飾と補助情報を見直す | 削除しても理解・判断・操作が保たれるか。ブランドや必要な画像は文脈で判断する |
| 削減 | 13 重複 | 同じ成功通知や説明の繰り返しを整理する | 一度で結果が分かるか。代替テキストや読み上げ用ラベルは保つ |
| 行動支援 | 14 即時Feedback | 操作の受付、処理中、結果を近い場所とタイミングに示す | 受付が分からず繰り返し操作しないか。完了していないのに成功表示しない |
| 記憶の外部化 | 15 状態 | 保存、選択、絞り込み、公開など現在の状態を示す | 消える通知だけに頼らず結果を把握できるか |
| 記憶の外部化 | 16 中断と復帰 | 要件に沿って入力、選択、現在地、完了済みの情報を保持する | 戻って作業を再開できるか。必要のない永続化を追加しない |
| 行動支援 | 17 次の行動 | 空状態、失敗、完了時に可能な次の操作を示す | 行き止まりにならないか。画面の説明やCTAを常に増やす規則にしない |
| 行動支援 | 18 メニュー名 | 内容を予想できる対象名・具体的な名称を使う | 名前から行き先が分かるか。「管理」「その他」へ異なるものを集めすぎない |
| 優先順位 | 19 Progressive Disclosure | 必須情報を見せ、文脈に応じた補助・高度な設定を段階的に示す | 必須操作を隠して探索・開閉が増えないか。低頻度でも危険や重要情報は見せる |
| 優先順位 | 20 Summary → Detail | 判断に必要な概要から、必要な詳細へ進めるようにする | 概要が結論の理由を落としていないか。詳細の存在と行き先が分かるか |
| 削減 | 21 必要な認知負荷 | 判断や信頼に必要な理由・情報を残す | 情報を削った結果、理由や選択の影響が分からなくならないか |
| 行動支援 | 22 Interaction Complexity | 遷移、戻る、再入力、展開、対象の切り替えも見直す | 見た目が簡素でも操作が複雑になっていないか。安全な確認は必要な手順として扱う |
| 行動支援 | 23 見た目と理解 | アイコン等の簡素さと意味の分かりやすさを分けて判断する | 推測が必要な記号にラベルを付ける。要素が増えても理解が改善することがある |
| 整理 | 24 一貫性 | 同じ対象・状態・操作に同じ表現を使う | 削除や保存の名前・位置・振る舞いを学び直さないか |
| 近接 | 25 エラー | 対象入力の近くで、分かっている原因と可能な対処を示す | 入力を失わず修正・再試行できるか。未確認の原因を断定しない |
| 整理 | 26 空白 | 関係と優先順位を余白・整列で表す | 関連情報が離れたり、比較や主要操作に余計なスクロールが必要にならないか |
| 優先順位 | 27 操作頻度 | 頻度と重要度に応じて常時表示・文脈表示・詳細を選ぶ | 主な作業を妨げないか。初回の必須設定を低頻度という理由だけで隠さない |
| 行動支援 | 28 推測 | 対象、現在地、違い、結果、次の操作を明確にする | 操作前に結果を予想でき、操作後に理解できるか |
| 全分類 | 29 6つの基本操作 | 削減・整理・優先順位・外部化・近接・行動支援を組み合わせる | 一つの分類だけを最適化せず、必須フロー全体で前後を比較する |

## 使い方の例

- **一覧と詳細**：対象を見分ける属性を一覧に置き、詳細へ移っても対象名を保持する。
  フィルターを適用しているなら条件を見せ、戻った際に維持する（4・15・18・22）。
- **フォーム**：恒常的なラベルと必要な入力条件を示し、失敗した項目の近くに対処を
  表示する。送信受付と結果を示し、入力を保持する（6・7・14・16・25）。
- **比較**：同じ観点を揃え、差を近くに見せる。Mobileでは比較対象を切り替えても
  条件が分かるようにする（8・10・23・26）。
- **密度の改善**：重複や弱い装飾を整理した後、主要情報を隠していないか、探す・展開する
  操作が増えていないかを確認する（1・12・13・19・21・22）。

「1画面1Primary Task」は現在の文脈で優先する目的を明確にする目安。
OOUIの一覧や詳細に必要な複数操作まで取り除かない。情報を少なくした画面と、
頭の中で処理することを減らした画面を分けて評価する。

候補と手がかりを提示する考え方は[NN/GのRecognitionとRecallの解説](https://www.nngroup.com/articles/recognition-and-recall/)、
必要な情報を保ちつつノイズを整理する考え方は[NN/GのAesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/)にも対応する。
作業記憶の研究からメニュー数等の固定上限を導かず、実際の作業で確認する。
