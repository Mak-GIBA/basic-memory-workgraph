# 共通レビュー基準

この基準は対象アプリ、比較アプリ、修正、再評価で共有する。
利用者と必須機能は現在の依頼を優先する。初見、誤操作、急いでいる、説明を読まない
視点を補助に使い、業務上必要な情報や熟練者向け操作を無条件に削らない。

## 過去の指摘を参照する

設計・レビュー・修正の開始時に、利用可能なBasic Memoryから関連する過去の指摘を検索して読む。
ハーネスの子ロールにも同じ手順を適用する。既に本文を確認したノートが渡されていれば再利用する。

1. ユーザーが指定した既存プロジェクト、ホストの設定、`basic-memory.json`の
   `primaryProject`から参照先を確認する。利用可能なMemoryツールを確認し、固定の
   プロジェクト名・ホーム・ツール名を仮定しない。
2. 今回の目的、利用者、対象・操作、出力、制約で検索する。Correctionsだけに限定せず、
   Rules・Workflows・Validations・関連するCasesや指摘を含むノートも候補にする。
3. 関連しそうなノートの本文を読み、元の文脈、対象版、適用範囲、例外、根拠の状態を
   今回と照合する。Caseは修正の順序と実際の結果も読む。一件の指摘を恒常的な好みと
   みなさず、現在の依頼と競合するものや対象外・古い条件をそのまま適用しない。
4. 適合する指摘を設計・確認の候補にする。今回の問題と解消状態は新しい画像と実操作で
   確認する。適用したノートの参照先と適用理由を、既存の設計メモ・所見・改善理由へ短く残す。

未導入、参照不能、検索失敗、該当なしは区別し、実際に読めた範囲だけ報告する。
該当するノートが読めなくても現在の依頼と観察に沿って作業を続ける。この参照手順は
読み取りのみとし、Memoryへの保存、導入、プロジェクト作成、設定変更は行わない。

## OOUIと操作の文脈

- 対象が見分けられるか。集合から詳細へ、詳細から関連対象へ辿れるか。
- 対象に何ができるか、その結果と現在の状態が分かるか。
- 対象を切り替える際、検索・選択・入力が失われず、戻れるか。
- 対象が固定の操作や意味のある固定手順にはタスク起点を使える。
  検索は集合の絞り込み、一括操作は対象集合への操作としても扱える。
  機能名、モーダルの数、メニューの名詞だけでOOUI適合や品質を判定しない。
- 新規作成は集合、行内操作はその行、一括操作は選択した集合が対象。
  一律に詳細画面や余分な「対象を選択」クリックを追加しない。
- Mobileでは別画面の一覧と詳細も使う。同時表示より対象名・戻り先・状態保持を優先する。

## 認知負荷

削減・整理・優先順位・記憶の外部化・近接・行動支援を確認する。
覚える、探す、比較する、対応付ける、推測する、行き来する負担を画像と実操作から
説明し、不要な往復、展開、再入力、意味の不明なラベルを記録する。

主要目的を明確にし、必要な対象・情報・操作を見つけやすくする。
操作を一つへ制限したり、必須情報を隠したり、説明を増やしたりするだけで改善としない。
ラベルやエラー原因・対処の表示、必要な確認の追加は、理解や完了への効果から判断する。
余白や装飾を減らした後も、比較、発見、重要度の把握、アクセシビリティを保つ。

## 記録と再評価

- 画面の所見では対象・ビュー・操作の文脈、適用した使い分けと理由を書く。
- フローの摩擦では、ユーザーが何を覚え・探し・推測する必要があるかを具体化する。
  重大な障害は指摘と重要度にも反映する。
- 操作数は代表フローと数え方を明記する。往復、再入力、判断箇所、Mobileの密度の
  変化を同じフローの前後画像と操作に対応付ける。負荷や満足度の測定値とは呼ばない。
- `simplicity.regressed`は必須情報の隠蔽、探索・往復・再入力の増加、状態の喪失、
  対象や結果の分かりにくさ、競合する情報の増加などが主要操作を難しくした場合に使う。
  要素数が増えたという理由だけでは使わない。
- 画像上の構造、機能の充足、表示不具合、実操作の完了を別々に確認する。
  未確認、仮応答、適用外を区別する。OOUIの形式だけで合格にしない。

日本語UI文言、設計メモ、レビュー・比較・改善レポートの下書きには、利用可能な
yomiyasuを読んで一度推敲することを推奨する。主張、専門用語、数値、ID、条件、
確認結果、根拠、断定の強さを保ち、短いラベルを長文化しない。子ロールはレポートに
使う説明欄をJSONへ返す前に整え、キー・列挙値・証拠リンク・引用・生ログを保持する。
公開後の生成済みレポートや保存版を直接推敲しない。未導入でも執筆・文言確認を続け、
この実行からインストールや設定変更を行わない。

必要な詳細は同じディレクトリの `ooui-modeling.md`、`cognitive-load.md`、
`quality-gates.md` を読む。出典と解釈の範囲は `sources.md` にある。
