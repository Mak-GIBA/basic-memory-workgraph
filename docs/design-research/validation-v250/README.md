# Design Research 2.5.0 の汎用ワークフロー検証

2026年10月11日。MCP選定以外の比較実験、原典に基づく設計判断、不具合修正を対象に、実際のCodexモデル・親の実行器・採点器・独立レビューを使って確認しました。

最小設計と実験資材を先に作り、実出力と主要指標を保存してから、原典確認・詳細説明・項目別レビューを行う構成です。大きな原典や台帳は全文とハッシュを持つ参照へ渡し、子の初期入力は指示込みで16 KiB以内にします。必須工程が残る間は全体を完了扱いにしません。モデル工程の既定上限1800秒は保持し、今回の実試行は各工程600秒で行いました。

アルゴリズム比較の差は空白付きの2入力です。`" true "`ではAが`"invalid"`、Bが`true`を返し、`"\tfalse\n"`ではAが`"invalid"`、Bが`false`を返しました。他の5入力は同じ出力です。計画や正解の書き写しを実行結果として使わず、実際の関数の戻り値と固定した正解を別々に保存しました。実験は1件で、途中の形式修正やレビュー再開の際に再実行していません。

最初の完成報告には完了済みの説明・レビューを「待機中」とする古い記述が残りました。実験・採点・固定条件・全入力参照のハッシュを確認し、追加の報告確認unitだけを実モデルで実施しました。前のstateと報告、確認の応答を保存し、採点値の一致と実験の未再実行を検証しています。最終報告は説明・レビューの完了を反映し、指定fixture内の正確さ以外の未確認事項は残しています。

詳細な手法説明と読み手向けの説明も必須工程として確認します。アルゴリズム比較では、凍結した比較範囲が基準案と1提案に限られるため、理由のある例外を使います。候補数を埋めるための方式は作りません。図の構造・出典・保存ファイルを検証し、説明用の図を実測に置き換えません。

3課題とも必須unitがすべてcompleteとなり、アルゴリズム比較・文献調査は`research_complete`、修正は`passed`です。両研究の方式判断は`provisional`のままです。文献調査は、完全なチェックポイントの公開が必要なら準備済みの一時ファイルからの置換を条件付きで選び、更新中断時の消失を許せるなら直接書き込みも選択肢とします。電源断後の永続化、遅延、故障頻度の優位は測定していません。元のman7取得失敗と、取得できた2021年の原典の版差も残しています。

## 開発中の停止と修正

モデルの形式誤り、実行資材の入力基準、原典取得の失敗、実出力JSONとreceiptの取り違えを保存し、成功した実験に混ぜていません。最終レビューには厳密な台帳・採点のエラー、実際のexport一覧、成功したreceipt、完了済み工程を渡します。台帳全体を再生成せず、元台帳のハッシュに結びつけた必要な節の置換を返し、親が全文を復元して従来の厳密な検証を適用します。

取得に失敗した原典を結論の支持に残していた例では、暫定判断を書くだけでは完了できません。実際に取得・読解できた原典を別IDで登録し、支持する箇所の参照先を対応させます。失敗したURLと取得記録は保持します。現在の構成では、この不整合を最終unit内で検出し、比較設計からやり直しません。形式・参照の修正は元の期限内で1回までです。

更新途中の版では、出典のlocatorを変えた不正なモデル出力が、親の出典照合より先にcompleteとして保存された例もありました。この実験用unitは元状態・入力・出力・ハッシュを保管し、出典不整合の確認後に再検証対象へ戻しました。最終版は既登録の出典との照合、新規IDの重複、空のtitle・locator、参照先の欠落をcheckpoint前に検査し、不正な応答を完了保存しません。通常の保存済みunitの入力・出力、固定条件、実行receiptを手修正して通す処理は加えていません。

実試行は更新途中の版から最終版へ再開した確認を含みます。初回から全てが無停止で終わったという試験ではありません。以前の`producer-design`が1800.009秒で停止したMCP課題とは課題・構成が異なるため、所要時間を直接比較して一般的な速度改善率を出しません。
