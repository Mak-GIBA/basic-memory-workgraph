# Codex UX Stack：使い方

[概要と収録ツール](README.md) · [導入手順](installation.md) · [docs一覧](../README.md)

## 最初の操作

導入後にCodexを再起動し、作業するアプリのフォルダーでセッションを開始します。
以下はCodexへの依頼例です。画面名・対象ファイル・URLは自分のプロジェクトに置き換えてください。
pluginの選択方法は利用中のCodex UIに従い、Skillは入力候補から選べます。

## デザインの方向性を考える：Product Design

```text
Product Designを使って、予約管理アプリの一覧画面を検討してください。
利用者は店舗スタッフで、今日の予約と未対応の予約をすぐ把握したいです。
まずデザイン案を比較できる形で提示し、選んだ案から操作できる試作を作ってください。
```

既存画面なら対象のスクリーンショット、URL、ローカルの実装も指定します。
期待する成果はデザイン案、試作、またはレビューです。公開が必要な場合は、共有先を別途指定します。

## Webアプリを実装する：Build Web Apps

```text
Build Web Appsを使って、このプロジェクトに予約一覧画面を実装してください。
既存の技術構成とコンポーネントを確認し、日付と状態で絞り込めるようにしてください。
読み込み中・データなし・取得失敗の表示も作り、ブラウザーで動作を確認してください。
```

既存プロジェクトのコードやテストが成果物になります。
React等の補助Skillは必要に応じて使います。インストールだけでStripeやSupabaseへ接続されるわけではありません。

## UIコードを確認する：web-design-guidelines

```text
$web-design-guidelines 予約一覧画面のUIコードをレビューしてください。
キーボード操作、フォーカス、フォームのラベル、エラー表示を中心に、
該当箇所と改善案を示してください。まず指摘だけをまとめてください。
```

コード上の指摘と改善案を得る用途です。実ブラウザーでの操作も確認したい場合は、次の依頼を併用します。

## 実際の操作を確認する：Playwright MCP

アプリをそのプロジェクトの手順で起動し、到達できるURLを指定します。

```text
Playwright MCPで http://localhost:3000 を開いて、
日付の絞り込み、予約詳細への移動、一覧へ戻る操作を確認してください。
狭い画面幅でも確認し、操作結果と気づいた問題を報告してください。
```

操作結果の報告が得られます。スクリーンショットや検証記録をファイルで残したい場合は保存先も指定します。
MCPの登録確認とは別に、ブラウザーが起動できること、対象URLへ到達できることが必要です。

## 根拠付きのUX批評を行う：ux-critique

インストーラーの`--deep`で追加した環境だけで使えます。

```text
$ux-critique --standard
この予約詳細画面を、初めて使う店舗スタッフの視点でレビューしてください。
予約変更の見つけやすさと、取り消し操作からの復帰を重視してください。
改善理由と具体案をチャットにまとめてください。
```

ここでの`--standard`はSkillへの依頼であり、シェルの引数ではありません。
複数画面の流れを詳しく見たい場合は、対象とともに`--deep`を指定します。
チャットで批評を受け取るだけならFigma接続は不要です。
[提供元のCodex利用方法](https://github.com/Thecsiz/ux-critique#run-it-in-codex)

## 成果物の置き場所

このインストーラーは、レビューや試作を保存する共通フォルダーを作りません。
コードは作業対象のプロジェクト、指摘はチャットまたは指定した文書に残します。
ファイルが必要な場合は「レビューを`docs/ux-review.md`へ」「画像を`artifacts/ux/`へ」などと指定してください。
これらは保存先の例であり、インストーラーが自動作成するパスではありません。
